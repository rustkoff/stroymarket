# Соответствие методичке: ПР 3–4

Источник: `data/Практикум_Интернет_технологии.pdf`, с. 8–10; правила отчёта из `data`.

| Пункт | Реализация и доказательство |
| --- | --- |
| ПР 3.1: ≥3 связанные таблицы | users, products, cart_items, orders, order_items; дополнительные sessions, feedback, login_attempts. Схема и поля в README |
| ≥15 записей | 12 прежних товаров + фанера ФК 6, 15 и 18 мм с источниками |
| Список, один элемент, регистрация, вход, запись | JSON API каталога; серверные HTML-страницы; POST регистрации, входа, корзины, заказа, обратной связи |
| Данные страниц из сервера | Jinja2 получает каталог, товар и корзину из SQLite; фильтры и калькулятор ПР 2 сохраняются |
| Учётные записи и закрытые данные | Профиль, корзина и история заказов; проверка владельца на сервере |
| Хеши и параметризованный SQL | argon2-cffi; sqlite3 с плейсхолдерами; автоматические проверки |
| ПР 4.1: зависимости и настройки | Закреплённые requirements, .env.example; DATABASE_PATH, PUBLIC_ORIGIN, COOKIE_SECURE |
| Dockerfile и чистый запуск | Образ Python, непривилегированный UID, healthcheck; сборка без рабочей БД |
| Публикация и HTTPS | https://rustkoff.ru через существующий Nginx и Reality fallback; сертификат Let's Encrypt |
| README и тестовая запись | Инструкции, адрес; проверяющий создаёт собственную учебную запись, общая учётная запись с опубликованным паролем отсутствует |
| Отчёт | Сохранение ПР 1–2, схема БД, /docs, безопасный пример хеша, сборка/контейнер, опубликованный HTTPS; рендер DOCX и сверка страниц |

Обратная связь после ПР 3 сохраняется для вошедшего пользователя в SQLite. Почтовая доставка не настроена и не заявляется. Внешний API остаётся справочным, цены учебные.
