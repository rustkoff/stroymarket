# Техническое задание: «СтройМаркет», вариант 14

## Назначение и цель

«СтройМаркет» — учебный адаптивный веб-сайт для подбора строительных материалов. Проект выполняется по варианту 14 дисциплины «Интернет-технологии». Его основная особенность — калькулятор количества материала по площади или объёму; каталог и карточки помогают выбрать подходящий товар. Цель проекта — последовательно освоить HTML/CSS, JavaScript и сетевые запросы, серверную разработку, хранение данных и подготовку приложения к публикации.

## Пользователи и основные сценарии

Посетитель просматривает каталог, фильтрует товары, открывает карточку, рассчитывает нужное количество материала, добавляет товары в корзину и узнаёт контакты магазина. Зарегистрированный пользователь может войти в аккаунт и продолжить работу со своей сохранённой корзиной. Сайт не оформляет реальную покупку и не принимает оплату: это учебный каталог.

## Страницы и навигация

Общее меню доступно на каждой странице; связанные страницы ведут друг на друга.

| Страница | Содержание и ожидаемое действие |
| --- | --- |
| Главная (`/`) | Назначение магазина, переходы к категориям и 5–6 рекомендуемым товарам с изображениями и ссылками на карточки. |
| Каталог (`/catalog`) | Полный каталог (не менее 15 осмысленных товаров), категории, цена и базовые характеристики; фильтрация и сортировка. Вёрстка соответствует минимуму ПР 1 — 12 позиций. |
| Товар (`/product/{id}`) | Изображение, описание, единица продажи, цена, характеристики и действие добавления в корзину; ссылка на расчёт материала. |
| Калькулятор (`/calculator`) | Выбор товара/типа материала, ввод площади или размеров/объёма и параметров расхода; результат в понятных единицах. Количество упаковок округляется вверх. Формула и допущения показываются пользователю. |
| Корзина (`/cart`) | Выбранные товары, количества, изменение/удаление позиций и итоговая сумма. Для вошедшего пользователя корзина сохраняется на сервере. |
| Контакты (`/contacts`) | Учебные контактные сведения магазина и форма обратной связи с проверкой обязательных полей. Не размещать вымышленные реальные адреса/телефоны как действующие контакты. |
| Аккаунт (`/account`) | Регистрация, вход и состояние профиля; доступ к персональному содержимому только после серверной проверки авторизации. |

## Данные и поведение

Клиентская часть использует семантический HTML, общий внешний CSS и JavaScript. Каталог и карточки получают данные через API приложения, а не из неизменяемой разметки. Интерактивность без перезагрузки включает фильтрацию/сортировку, расчёт и обновление корзины. Для ПР 2 нужны как минимум две интерактивные формы (например, обратная связь и калькулятор/подбор — без формы входа), проверка ввода с сообщением у поля и как минимум два элемента динамического обновления. Для запросов отображаются состояния загрузки и понятная ошибка с сохранением работоспособности интерфейса.

Сервер — Python/FastAPI, база данных — SQLite. Минимальная модель: товары, пользователи и позиции корзины с внешними ключами; у пользователя может быть несколько позиций корзины, каждая позиция ссылается на товар. Каталог содержит не менее 15 осмысленных записей. Предусмотреть API списка и отдельного товара, регистрации/входа, получения и изменения корзины. Пароли хранить только в виде стойкого хеша с библиотекой; все SQL-запросы параметризовать. Персональные операции и данные защищать проверкой пользователя на сервере, а не только скрытием элементов интерфейса.

Курс валют получать асинхронно через `fetch` из JSON-источника курсов ЦБ РФ `cbr-xml-daily.ru`; использовать его для дополнительного показа цены в другой валюте, а не для изменения базовой цены товара. Показывать загрузку и обработать сетевую ошибку/недоступный источник.

## Требования к качеству и приёмке

- Все страницы связаны меню; в документе указан язык, UTF-8, `viewport`, один заголовок первого уровня, осмысленные `alt` у изображений и логичная вложенность заголовков.
- Общая таблица стилей подключена отдельно; макет на Grid/Flexbox. При ширине 360 px нет горизонтальной прокрутки, меню доступно, изображения не переполняют контейнеры. Доступна клавиатурная навигация и читаемый контраст.
- Есть минимум две интерактивные формы с проверкой ввода и сообщениями у полей, два динамических элемента, состояния загрузки/ошибки для внешнего запроса.
- Проверить работу форм, фильтров, калькулятора, корзины и авторизации, включая ошибочные данные и отказ API; интерфейс не должен ломаться при недоступности сети.
- Сервер возвращает данные из SQLite; проверить минимум 15 товаров, регистрацию/вход, изоляцию пользовательской корзины, хеширование паролей и параметризованные SQL-запросы.
- Перед сдачей сверить запуск с README. Публикация, Docker и HTTPS относятся к ПР 4 и считаются выполненными только после фактической сборки, развёртывания и проверки адреса.

## Этапы

1. ПР 1: связанная адаптивная разметка, единый стиль и навигация.
2. ПР 2: клиентская интерактивность, проверки форм и внешний курс валют.
3. ПР 3: FastAPI, связанная SQLite-модель, API, регистрация/вход и персональная корзина.
4. ПР 4: воспроизводимый запуск в Docker, конфигурация вне кода, размещение и HTTPS.

Это спецификация целевого учебного проекта, а не подтверждение того, что перечисленные функции уже реализованы или опубликованы.
